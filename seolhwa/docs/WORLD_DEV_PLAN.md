## 1. 현재 위치와 전제

### 1.1 지금까지 만든 것 (개발계획서 v1 기준 1~3단계 완료)
| 단계 | 결과 | 월드 개발에서의 의미 |
|---|---|---|
| 1단계 비주얼 | 고정 시점 3D + 민화풍 2D, 시간대·후처리 | 레벨 3 맵의 **렌더 기준**이 확정됨 |
| 2단계 전투 | 호랑이 전투, 예고 동작, 결말 4종 | 지형이 전투 공간을 만족해야 함(§32) |
| 3단계 사건 | 「산길의 실종」 조사→해결→지역 변화 | 레벨 3 맵이 갖춰야 할 **사건 인터페이스**(anchors, setState, 싸움터)가 확정됨 |

현재 프로토타입의 산골 마을은 **스타일 검증용 무대**다. 강과 길이 장식처럼 놓여 있어 명세서 §2 제작 순서를 따르지 않는다. 월드 파이프라인이 완성되면 이 무대는 파이프라인 결과물로 **다시 만든다**(사건 스크립트·전투·UI는 그대로 재사용).

### 1.2 범위를 지키는 원칙
- 개발계획서 v1 27장의 순서를 유지한다. 다음은 **4단계 버티컬 슬라이스**(지역 하나 + 사건 3~5개)다. 조선 전체를 한 번에 만들지 않는다.
- 대신 **조선 전체의 "뼈대 데이터"(레벨 0)는 처음부터 만든다.** 지역 하나를 만들더라도 그 지역의 강이 어디서 와서 어디로 가는지, 어느 고개로 다른 권역과 이어지는지가 전국 단위로 맞아야 하기 때문이다.
- 지형은 **"고증된 뼈대 데이터 + 절차적 세부"** 로 만든다. 명세서 §33 금지 1(평지 위 랜덤 산)과 금지 10(사료와 충돌하는 임의 창작)을 동시에 지키는 유일한 방법이다.

### 1.3 반드시 짚어 둘 한계
- **사료 정확성**: AI 에이전트의 역사지리 지식에는 오류가 있다. 모든 지명·위치·연결 관계에는 **출처 태그와 신뢰도**를 붙이고, 사람(역사지리 검수자)의 검토 게이트를 통과해야 확정된다. 에이전트가 만든 데이터는 "초안"이다.
- **대동여지도 원자료**: 이 작업 환경에서는 규장각·국립중앙도서관 디지털 원문에 접근할 수 없다. 고지도 판독·디지타이징(22첩 도엽의 하천·도로·고을 좌표화)은 **사람이 확보한 디지털 자료**를 입력으로 받아야 정확해진다. 그 전까지는 에이전트 지식 기반 초안으로 진행하고 검수 표시를 남긴다.
- **엔진**: 본 제작 엔진은 **Godot 4**로 확정했다(§11). 웹(three.js) 프로토타입은 스타일·전투·사건의 **기준선**으로 보존하고, G0 단계에서 Godot으로 이식한다. 월드 생성 파이프라인은 엔진 밖 도구로 만들고 산출물은 **엔진 중립 형식**(16비트 높이맵 PNG, JSON 그래프, glTF, 텍스처 아틀라스)을 유지한다.

## 2. 월드 구조: 레벨 0~3 (명세서 §31 구체화)

| 레벨 | 단위 | 내용 | 해상도/규모(안) | 플레이어가 보는 방식 |
|---|---|---|---|---|
| **L0** | 조선 전체 | 대간·정맥, S/A급 강, 감영·주요 고을, 대로, 대표 고개 | 위상 그래프 + 1px≈1km 높이맵 | 대동여지도풍 **여행 지도 UI** |
| **L1** | 팔도 | B급 지류, 모든 고을, 9대로·지선, 역·원, 진·나루 | 1px≈250m | 도(道) 지도, 이동 경로 선택 |
| **L2** | 수계·분지·교통권 (예: 남원·운봉·지리산권) | C급 하천, 분지·평야·단구, 장시·주막·사찰·성황당 위치, 토지이용 | 1px≈25m (지역당 약 20~40km 압축) | 권역 지도, 여행 연출, 플레이 맵 선택 |
| **L3** | 플레이 맵 (예: 남원읍성, 운봉 마을, 뱀사골) | 실제 3D 지형·건물·식생·사건 장소 | 0.5~1m 격자, 맵당 약 0.3~1.5km | 고정 시점 3D 플레이 |

- **압축 규칙(명세서 §30)**: L0→L2에서 거리는 압축하되 **순서·방향·상하류·분수계·합류·고개 관계는 보존**한다. 예: 남원은 운봉보다 서쪽 저지대, 운봉은 분수계 위 고원, 요천은 섬진강으로 간다.
- **L2→L3**: L3 맵은 L2 데이터를 잘라 확대하고, 세부를 절차적으로 채운 뒤 **레벨 디자이너가 플레이 공간을 다듬는다**. L3에서 강의 방향·고개 위치를 바꾸면 안 된다(바꾸려면 L2부터 수정).

### 2.1 월드 위상: 권역 심리스 + 압축 노정 (확정)

```
[남원·운봉·지리산 권역] ──노정: 남원→전주── [전주 권역]
   격자 타일, 실축척에 가까움        길 따라 늘어선 타일, 압축 축척
            ╲
             ──노정: 운봉→함양→…→문경새재── [문경새재 권역]
```

- **권역(Region)**: 하나의 수계·분지·교통권. 내부는 **로딩 없이 이어지는(심리스)** 격자 타일 공간이다. 플레이 축척은 실축척에 가깝게 하되 권역 하나가 약 4~8km를 넘지 않도록 압축한다. 마을·읍성·산·사건이 있는 곳이다.
- **노정(Route)**: 권역과 권역을 잇는 실제 도로(대로·지선)를 **"걸어 들어가는 노정도(路程圖)"** 로 만든 길 공간이다. 실제 도로가 지나는 고을·역·원·주막·나루·고개의 **순서·좌우 지형·고도 흐름은 보존하고 거리만 압축**한다. 폭 150~300m의 플레이 가능한 띠, 그 바깥은 L0 데이터로 만든 먹빛 능선 그림판(원경).
- **연결점(Portal)**: 권역과 노정은 고개·나루·장승·관문에서 로딩 없이 이어진다. 연결 타일은 양쪽이 같은 지형으로 맞물리게 생성한다.
- **좌표계**: 권역과 노정은 각자의 **로컬 좌표계**를 가진다(노정은 압축 축척이라 실제 지리와 어차피 일치하지 않는다). 공간 하나가 수 km 이내라 부동소수점 정밀도 문제가 생기지 않는다. 실제 지리 위치는 여행 지도 UI에서만 쓴다(노정 위 위치 → 실제 도로 위 위치로 보간 표시).

**노정 압축 규칙**
| 보존 | 압축 |
|---|---|
| 지나는 고을·역·원·주막·나루·고개의 순서 | 고을 사이 거리 |
| 강을 건너는 위치와 방법(큰 강은 나루) | 평범한 들길, 반복되는 농촌 |
| 오르막·내리막 흐름(실제 고도 단면 축소) | 긴 직선 구간 |
| 길 좌우에 산·강·평야가 놓인 방향 | |

- **압축 비율(초안)**: 실제 하루 길(약 80~100리)을 플레이 **3~5분**으로. 영남대로 전 구간(한양~동래)이 걸어서 약 40~70분.
- **길 위의 플레이**: 주막·원(휴식, 저장, 밤으로 시간 전환, **소문으로 사건 발견**), 나루(뱃사공·배 기다림·도깨비 이야기 후보지), 고개(성황당·날씨·조우), 장승·역(거리 표시·갈림길), **여정 사건**(권역 사건보다 작은 에피소드, 기존 조사·전투·대화만 사용).
- **재방문**: 한 번 걸어간 노정은 **역마·나룻배·조운선**으로 빠르게 이동할 수 있다(처음 길만 모험).

### 2.2 타일 스트리밍 규격 (초안)

| 항목 | 값 |
|---|---|
| 권역 타일 | 256m × 256m 격자, 지형 1m 격자(257² 높이값), 이웃 타일과 가장자리 정점 공유 |
| 노정 타일 | 길 중심선(스플라인)을 따라 256m 구간 × 폭 300m |
| 근경 | 플레이어 주변 반경 2타일: 지형·건물·식생·NPC·사건 전부 |
| 중경 | 그 바깥 1~2타일: 저해상도 지형 + 큰 실루엣만 |
| 원경 | 권역·노정별 먹빛 능선 그림판(L0·L1 데이터로 생성), 안개 띠 |
| 로딩 | 백그라운드 스레드 로딩, 이동 방향으로 1타일 선행 로딩, 프레임 정지 0 목표 |
| 경계 걸침 물체 | 성벽·긴 다리·큰 마을처럼 타일 경계를 넘는 것은 "셀 묶음"으로 함께 로딩 |
| 상태 저장 | 사건으로 바뀐 지역 상태(`setState`)를 공간·타일 단위로 저장, 타일 재로딩 시 적용 |
| 예산(타일당, PC 기준 초안) | 삼각형 6만 이하, 그리기 호출 40 이하, 텍스처는 공용 아틀라스 |

고정 시점이라 화면에 보이는 범위가 반경 50~100m 수준이다. 그래서 자유 카메라 오픈월드와 달리 원거리 대체물(HLOD)이나 대형 스트리밍 시스템이 필요 없다.

## 3. 월드 데이터베이스 (단일 진실 원천)

모든 에이전트는 **`world/db/`의 데이터를 통해서만** 협업한다. 3D 자산·맵은 이 데이터에서 파생된다.

```
world/db/
  schema/                    # JSON Schema (모든 파일 검증)
  L0/
    ridges.json              # 대간·정간·정맥 폴리라인 {id, name, rank, points[], source, confidence}
    rivers.json              # 하천 그래프 {id, name, grade S|A|B|C|D, mouth_to(river_id|sea), source_region, points[]}
    basins.json              # 유역 폴리곤 (ridges에서 파생)
    passes.json              # 고개 {id, name, ridge_id, connects:[basin,basin], elevation_class}
    crossings.json           # 나루·여울·다리 {id, type, river_id, road_ids, size}
    roads.json               # 대로·지선 {id, name(의주대로 등), class, nodes[]}
    settlements.json         # 고을·도시 {id(GG-01 등), name, type, river_id, road_ids, admin}
    folklore.json            # 설화 {id, title_internal, grade A+|A|B|C|D, regions[], env_tags[]}
  L1/<province>/...          # 도 단위 세분 데이터
  L2/<region_id>/
    region.json              # 명세서 §35 필수 양식
    heightmap.png (16bit), flow.png, landuse.png, ...
  L3/<map_id>/
    map.json                 # 플레이 맵 정의(anchors, arenas, cameraZones, interiors, 사건 연결)
  routes/<route_id>/         # 노정(압축 길 공간)
    route.json               # {id, road_id, from_region, to_region, stops:[{type:역|원|주막|나루|고개|고을, ref, t(0~1)}], compression, portals}
    profile.json             # 실제 도로를 따라 자른 고도·좌우 지형 단면(압축 전)
    spline.json              # 압축 후 길 중심선과 타일 분할
  tiles/<space_id>/<tx>_<tz>/ # 엔진 가져오기용 타일 산출물(높이맵·배치 목록·glTF 참조)
  sources/                   # 출처 목록, 고지도 판독 노트
  review/                    # 사람 검수 기록(승인/보류/수정 요청)
```

- 모든 레코드에 `source`(사료·문헌), `confidence`(확정/추정/가설), `status`(초안/검수중/승인)를 둔다.
- 생성 단계 잠금(§4): 앞 단계 데이터가 `승인`되기 전에는 뒷단계 에이전트가 그 지역을 수정할 수 없다.

## 4. 생성 파이프라인 (명세서 §2.1의 12단계 → 실행 가능한 의존 그래프)

| 단계 | 명세서 | 입력 | 처리 | 출력 | 담당 |
|---|---|---|---|---|---|
| P1 산줄기 | 1 | 산경표 체계, 고지도, (선택) 공개 DEM | 대간·정맥 폴리라인 → 능선 높이장 생성, 지능선·암봉·산록 프로파일 | `ridges.json`, 기반 높이맵 | 산줄기 |
| P2 유역 | 2 | 능선 | 분수계로 유역 분할 | `basins.json` | 수문 |
| P3 계곡·지류 | 3 | 높이장 | 흐름 방향(D8)·누적량 계산, 계곡 침식 | flow 맵, 계곡선 | 수문 |
| P4 본류 | 4 | 누적량 + 고증 하천 제어선 | 하천 추출, Strahler 차수 → 명세서 등급 S~D 매핑, **합류 구조 강제** | `rivers.json` | 수문 |
| P5 퇴적 지형 | 5 | 하천·경사 | 곡저·충적평야, 하안단구, 모래톱, 하중도, 습지, 삼각주 판정 | 지형분류 맵 | 지형학 |
| P6 고개 | 6 | 능선 | 능선의 안장점 중 낮고 양쪽 유역을 잇는 곳 → **고증 고개와 대조** | `passes.json` | 교통망 |
| P7 도강점 | 7 | 하천·도로 후보 | 하천 등급·폭으로 나루/여울/다리 결정(**큰 강은 나루 기본**) | `crossings.json` | 교통망 |
| P8 도로망 | 8 | 고개·도강점·경사 | 경사·하천 비용 최소경로(A*) — 계곡→산기슭→고개→나루→평야 | `roads.json` | 교통망 |
| P9 도시·읍성·장시 | 9 | 도로·하천·평야 교차 | 입지 점수(물·평지·교차·범람위험) + **고증 고을 위치 우선** | `settlements.json` | 취락 |
| P10 농촌·산촌·사찰 등 | 10 | 위 전부 | 명세서 §18·24·27~29 규칙으로 배치 | L2 POI | 취락·토지이용 |
| P11 역사 건축 | 11 | 고을 데이터 | 랜드마크(광한루, 영남루 등) 배치·고증 | 랜드마크 목록 | 건축 고증 |
| P12 설화·사건 | 12 | 완성된 지역 | 설화 등급(§22·23)으로 후보지 선정 → 사건 설계 | 사건 배치 | 설화·사건 |
| P13 노정 압축 | (추가) | 도로망 + 길을 따라 자른 실제 고도·지형 단면 | 정차지 순서 고정, 거리 압축, 고도 흐름 축소, 좌우 지형 재구성, 볼거리 배치, 권역과의 연결점 생성 | `routes/<route_id>` | 노정 설계 |
| P14 타일화 | (추가) | 완성된 권역·노정 | 공간 전체를 생성한 뒤 타일로 자름(경계 정점 공유), 셀 묶음 지정, 원경 그림판 생성 | `tiles/` | 지형 메시·스트리밍 |

- **고증 제어점이 절차 생성을 이긴다.** 절차 결과(예: 계산된 하천 경로)가 고증 데이터(실제 하천 경로)와 다르면 고증을 따르고, 높이장을 그에 맞게 깎는다(하천이 지형을 만든 것처럼 보이게).
- 각 단계 끝에 **자동 QA**(§6)를 통과해야 다음 단계로 간다.

### 4.1 DEM(실측 고도) 사용 방침
- L0~L1의 거시 형태는 공개 DEM(SRTM 등, 퍼블릭 도메인)을 낮은 해상도로 써서 실제 지형과 어긋나지 않게 한다. 단 **현대 댐 호수·직강화 하천·간척지는 제거**하고 고증 하천선으로 덮어쓴다(명세서 §1·§33 금지 8).
- L2~L3은 DEM을 압축·재해석한 위에 절차적 세부를 얹는다. 실측을 그대로 확대하지 않는다(압축 규칙 때문에 어차피 불가능).
- DEM 확보는 이 작업 환경 밖에서 사람이 받아 `world/db/sources/`에 넣는다.

### 5.1 슬라이스 권역 추천: **남원·운봉·지리산 서부** (JL-03·04·05 + 요천·섬진강)
- 명세서의 핵심 논리(**분수계 → 수계 → 취락**)를 한 지역 안에서 모두 보여 준다. 운봉고원은 백두대간 분수계 위에서 낙동강·섬진강 수계가 갈리는 곳이다.
- 지형 다양성: 저지대 읍성(남원) → 오르막 → 고원 분지(운봉) → 깊은 산·계곡(지리산) → 산 사이 강(섬진강).
- 설화 등급이 고루 섞여 **등급 체계를 시험**할 수 있다: 춘향 계열(A, 남원), 흥부 후보·우투리(B, 지리산권), 호랑이 이야기(D, 지리산 산림에 적합 — 「산길의 실종」을 이곳 산촌으로 이식).
- 대안: **문경새재(GS-01)** — 하나의 계곡·관문 축이라 범위가 작고 명확하다. 슬라이스 범위를 더 줄여야 하면 이쪽을 택한다.

### 5.2 권역 확장 우선순위(안)
1. 경상 북서: 문경새재·상주·안동·하회 (고개와 낙동강 상류 — 한강/낙동강 수계 연결 검증)
2. 경기: 한양·마포·송파·노량진 (최대 도시·나루·포구 체계)
3. 경상 남부: 밀양(아랑, A)·삼랑진·낙동강 하구
4. 충청: 충주·목계진·단양·공주·강경 (남한강·금강 수운)
5. 강원: 춘천·원주·치악산(A)·대관령·강릉
6. 전라 나머지: 전주·나주·영산포
7. 평안·황해: 평양·철산(A)·의주 / 재령평야·해주·장산곶
8. 함경: 철령·함흥·회령·육진
9. 제주: 별도 생성 규칙(방사형 경사, 오름, 용천수 취락)

## 6. 자동 QA (명세서 §36 + 추가 검사)

| 번호 | 검사 | 방법 |
|---|---|---|
| Q1 | 모든 하천이 바다 또는 상위 하천에 닿는가 | 하천 그래프 위상 검사 |
| Q2 | 하천이 이유 없이 능선을 넘는가 | 하천선 고도 단조 감소 + 능선 교차 검사 |
| Q3 | 큰 도시 주변에 안정적인 물이 있는가 | 도시 반경 내 B급 이상 하천 또는 우물·샘 |
| Q4 | 농경지가 산 정상에 있지 않은가 | 논=경사·고도 한계, 밭=구릉·산록 |
| Q5 | 주요 도로가 고개로 산맥을 넘는가 | 도로-능선 교차점이 모두 passes에 있는지 |
| Q6 | 큰 강을 건너는 지점이 있는가 | 도로-하천 교차점이 모두 crossings에 있는지 |
| Q7 | 마을이 상습 범람지 한가운데 있지 않은가 | 범람 위험도 맵 대조 |
| Q8 | 시장에 연결 도로가 있는가 | 그래프 연결성 |
| Q9 | 포구가 수운 가능한 수계에 있는가 | 하천 등급·수심 등급 |
| Q10 | 현대 시설이 남아 있지 않은가 | 금지 태그(댐·직강·철도·근대항만) 검사 |
| Q11 | 모든 강에 다리가 놓이지 않았는가 (§33 금지 3) | S/A급 도강점 중 다리 비율 상한 |
| Q12 | 모든 마을에 시장·모든 산에 사찰이 있지 않은가 (§33 금지 4·5) | 유형별 분포 상한 |
| Q13 | 설화가 등급 규칙을 지키는가 (§22·23·금지 6) | A+/A는 지정 지역만, D는 환경 태그 일치 |
| Q14 | 마을 입지가 "산 → 마을 → 밭 → 논 → 하천" 패턴인가 (§24) | 단면 샘플링 |
| Q15 | 레벨 3 가독성(§32) | 길 폭, 숲 간격, 처마 가림 비율, 전투 공간 확보 |
| Q16 | 성능 예산 | 타일당 삼각형·그리기 호출·텍스처 메모리 |
| Q17 | 노정의 정차지 순서가 실제 도로와 같은가 | `route.stops` ↔ `roads.json` 노드 순서 대조 |
| Q18 | 노정이 큰 강을 건너는 곳에 나루(또는 고증된 도강점)가 있는가 | 노정-하천 교차 ↔ `crossings.json` |
| Q19 | 노정의 오르막·내리막이 실제 고도 흐름과 같은 방향인가 | 압축 단면과 원 단면의 부호 비교 |
| Q20 | 타일 경계가 맞물리는가 | 이웃 타일 경계 정점 높이 일치, 하천·도로 연속성 |

## 7. 에이전트 조직

### 7.1 조직 구조
```
총괄(오케스트레이터)
├─ A. 고증·리서치 계층   — 사실을 만든다 (데이터의 "진실")
├─ B. 월드 생성 계층     — 땅을 만든다 (P1~P10 파이프라인)
├─ C. 권역 계층          — 지역을 책임진다 (권역별 담당)
├─ D. 자산 제작 계층     — 보이게 만든다 (모델·텍스처·식생)
├─ E. 레벨·게임 연동 계층 — 플레이하게 만든다 (L3 맵, 노정, 사건, 이동)
├─ F. 품질 계층          — 틀린 것을 잡는다 (QA·성능·시대 고증)
└─ G. 엔진 계층 (Godot)  — 돌아가게 만든다 (코어·렌더·스트리밍·가져오기 도구)
```

- 동시에 돌리는 에이전트는 **6~10개**로 제한한다. 비용과 통합 부담 때문이다. 단계별 투입 순서는 §7.3에 정리했다.

| 비용 | MIT 라이선스, 수익 분배 없음 |
| 감수할 점 | 콘솔은 포팅 업체 필요, 후처리·스트리밍은 직접 구현 |

- 언어: 게임플레이는 **GDScript**, 무거운 연산(필요 시)은 GDExtension. 월드 생성 파이프라인은 **엔진 밖 도구**(Python 등)로 만든다.
- 버전: 착수 시점의 **Godot 4 최신 안정판**으로 고정하고, 마이너 업그레이드는 G1이 검증 후 진행한다.
- 웹 프로토타입(`seolhwa/` 현재 코드)은 **스타일·플레이 기준선**으로 보존한다. G0 완료 기준은 같은 장면·같은 플레이를 Godot에서 재현하는 것이다.
