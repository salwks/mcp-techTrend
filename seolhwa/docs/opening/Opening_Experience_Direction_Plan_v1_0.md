# 설화록: 첫 실행 · 도입부 · 조작 · 시네마틱 · 지도/역마 전면 재설계

메인 스토리 1부(P00~M105) 적용을 위한 최초 플레이 경험 통합 기획서 | OPENING EXPERIENCE DESIGN v1.0

문서 성격: 기존 Story Bible v5.17과 메인 시나리오 1부 v1.0을 변경하지 않고, 실제 구현 지형 위에 첫 실행 UX와 연출을 얹는 별도 제작 기준. 초 단위 숫자는 초기 연출 목표값이며 게임 실행·플레이테스트 전 확정값이 아님.

# 0. 결론과 결정 사항

- 시작 위치: 남원읍성 안, 이겸의 거처로 쓰는 소규모 실내 공간. 현재 스타트 좌표(-2952, 184)는 그대로 사용하지 않고 새 게임 시작 지점을 씬에서 검증 후 교체한다.

- 첫 15분의 우선순위: 이동 → 살펴보기 → 대화 → 기록책 → 지도 → 웨이포인트. 전투와 역마는 각각 실제 필요 순간에 소개한다.

- 인트로 카메라: 전체 비조작 컷신 25초 이내(권장 18~22초); 4~6초 이하 개별 쇼트 중심. 전환 후 곧바로 조작.

- 타이틀: 새 게임 진입 중 메인 타이틀을 길게 재출력하지 않는다. 오프닝 플레이 6~10분 후 남원 전경에서 4.0초 등장·2.0초 페이드, 이동 중 조작을 잠깐만 제한.

- 지도: M 한 번에 지도 열기 → 마우스 휠 연속 줌 → 드래그 → 클릭 웨이포인트 지정 → E 또는 지도 버튼으로 안내 시작. 지도에서 표시한 목표는 직접 이동/역마 자동 이동 양쪽의 공통 목적지가 된다.

- 역마: 지도에서 목적지 선택 → 해당 노선의 자동 이동 가능 여부 표시 → 자동 이동 선택 → 안전한 탑승 지점에서 승마. 역참 NPC는 이동서비스/빌림 수단으로 유지하되 목적지 탐색의 유일한 출발점은 아니게 한다.

- 현 Godot 기능 존재는 코드 확인 결과. 실제 플레이 UX 결함, UI 입력 오작동·줌 떨림·경로 단절은 실행 로그·화면 녹화로 재검증해야 한다.

# 2. 플레이어 경험 설계 원칙

- 튜토리얼은 팝업 설명이 아니라 목표 달성 과정. 안내 문구는 1회 1행동, 행동 전 최대 2줄.

- 미스터리의 정답은 숨기되 현재 조작과 해야 할 다음 행동은 숨기지 않음.

- 카메라가 단서를 강제로 클로즈업하더라도 핵심 관찰은 플레이어의 E 조사 입력으로 확정.

- 메인 진행의 필수 단서에는 절대로 시간 제한을 걸지 않음. 대사를 건너뛰어도 기록책 요약 유지.

- 대화 상자와 조작 안내/역마/지도/기록책이 동시에 입력을 잡지 못하도록 인터랙션 소유권 1개로 제한.

- 구간별 자동저장: 집 조사 완료, 편지 수령, 주막 행적 확보, 성황당 도착, 사자 사건 해결.

| 신규: 옛길 입구 | 실제 도로/고개 데이터와 충돌하지 않는 작은 갈림길·낡은 표식·발자국 상호작용 배치. 도깨비 반복길과 5장 길돌림 장소 분리. | 도로 그래프/경사/시야 현장 렌더 검수 |



배치 원칙: `placement_story_main_intro.json` 신설. 각 객체는 고유 id, kit, x/y/z, ry, group, note, INTERACT_ID, SCENE_ID, PERSIST_FLAG를 갖고, 생성기 검증→시각 QA→Godot 실행→지형 충돌 검사 순으로 반영한다. 실제 파일 스키마에 없는 키는 별도 story manifest에 두어 loader를 파손하지 않는다.

# 8. 지도 UX: 연속 줌과 웨이포인트 중심으로 통합



| 입력 | 예상 동작 | 세부 품질 기준 |

|---|---|---|

| M | 지도 열고 닫기 | 지도 열 때 세계 이동 차단, 이전 줌/중심 유지 |

| 휠 위/아래 | 마우스 커서 위치를 앵커로 연속 확대/축소 | 1틱 배율 1.15~1.2배 제안, 최소/최대에서 튐 없음 |

| 좌클릭 빈 지도 | 그 위치에 목표 핀 설정 | 이미 알거나 방문한 육지/이동가능 타일은 직접 지정 가능 |

| 좌클릭 장소 아이콘 | 짧은 장소 정보 팝업, ‘목표로 지정’ | 서로 겹칠 때 아이콘 우선, 빈 지도 오선택 방지 |

| 드래그 | 지도 평행 이동 | 드래그 이동 6px 이상은 클릭으로 취급하지 않음 |

| 우클릭 핀 | 핀 해제 또는 이동 | 확인 없이 즉시 해제 가능; 메인 퀘스트 목표 자체는 삭제되지 않음 |

| Tab | 고을/권역/전국 LOD 단계 선택 보조 | 휠 배율 중심. Tab 없이도 충분히 조작 가능하게 |

| 지도 목표 선택 | 수동 안내/자동 역마 가능 여부 표시 | “현재 위치→목적지” 일관된 상태 저장 |

| Esc | 열린 팝업 닫기→지도 닫기 | 상단 메뉴/대화로 이벤트 전파 방지 |



연속 줌 구현식: map_world_under_cursor_before = screen_to_world(pointer); zoom = clamp(zoom * pow(1.17, wheel_delta), min,max); center를 보정하여 같은 세계점이 포인터 아래 남게 한다. LOD 전환 시 광학 배율이 갑자기 리셋되면 안 된다. 배경 이미지 텍스처 해상도에 따라 LOD는 뒤에서 자동 전환하되 중심 좌표와 핀은 유지.

엘든링식 UX에서 가져올 원칙: 지도 위 목적지 직접 선택, 빠른 스캔, 핀 설치와 이동 경로의 명확한 구분. 특정 게임 UI를 그대로 복제하는 것이 아니라 설화록의 한지·먹 고지도 디자인으로 구현한다.

# 9. 역마 UX: 지도 웨이포인트 → 노선 → 자동 기승

상태흐름: MAP_OPEN → DEST_SELECTED → ROUTE_COMPUTED → (MANUAL_GUIDE | AUTO_RIDE_ELIGIBLE | FAST_TRAVEL_ELIGIBLE) → MOUNT_POINT → AUTO_RIDE → EVENT_GATE/DISMOUNT → FOOT_APPROACH. 목적지는 지도에서 먼저 정한다. 역참 대화는 말 빌리기·요금·이동 설명 등의 게임 내 상호작용으로 유지.



| 상황 | 표시 | 조작/결과 |

|---|---|---|

| 선택한 지점이 걸어서만 가능한 숲속 | “이곳은 산길이다. 큰길까지만 역마 이용 가능” | 가장 가까운 안전 하차점 제안, 강제 순간이동 없음 |

| 알고 있는 큰길 거점 | “역마 자동 이동 가능” | 지도에서 ‘자동 이동’ 선택 후 탑승 지점까지 걸어가기 |

| 아직 방문하지 않은 지역 | “길을 직접 확인해야 한다” | 기존 routes_done 정책 유지, 자동 순간이동 불가 |

| 이동 중 사건 접근 | “앞에 일이 있다” | 70~200m 접근 자동 감속 후 하차, 1회 사건 트리거 |

| 노선 없음/막힘 | “이 방향은 이어지는 큰길이 없다” | 수동 안내 유지, 경로를 그려 놓고 말이 제자리 도는 현상 금지 |

| 탑승 중 | 현재 목적지·남은 거점·내리기 표시 | S 중지/계속, E 하차, Space 다음 정지 지점으로 건너뛰기 |



서로 다른 기능의 “빠른 이동(방문한 역참 건너뛰기)”과 “자동 기승(실제로 달리는 말)”은 지도에서 분리해 표시한다. NPC나 깃발에서 지도 열기는 부수 진입 방법으로 유지한다.

# 10. 대화 시스템 전면 정리: 인풋·카메라·서사 제어

단일 대화 상태: IDLE → APPROACH_HINT → STARTING(입력 잠금) → PLAYING → CHOICE → ENDING(카메라 복원) → IDLE. 대화 인물 거리 이탈·게임 저장·씬 전환 중에는 중복 실행 금지. CHOICE 선택 후 0.15초 입력 쿨다운, E 한 번으로 대사 두 줄을 넘기는 문제 방지.



| 결함 유형 | 수정 설계 | QA 검사 |

|---|---|---|

| 대사 반복/중복 | interaction transaction id로 한 번만 커밋; 마우스/E 이벤트 중복 처리 차단 | 100회 연타 테스트 대사 1회 진행 |

| 대화 끝나도 이동 불가 | ENDING의 rig 원복 성공/타임아웃 후 movement_owner 해제 | 대화 취소·씬 변경 50회 |

| 대화 중 지도 열림 | INPUT_OWNER = DIALOGUE에서 M/R/탑승 비활성화 | 키조합 매트릭스 테스트 |

| 선택지와 대사 포커스 혼란 | 선택지만 방향키·숫자 수신, 대사 클릭은 별도 | 마우스/게임패드/키보드 경로 |

| 유저가 말하는 인물 불명확 | 이름표·화자 전환 0.2초·대화 시선 정렬 | 인물 2~3명 대화 전환 |

| 재실행 후 대화 재발생 | 진행 플래그와 시청 여부 분리, 스킵해도 핵심 결과 커밋 | 저장/로드 각 상태 테스트 |

# 13. QA 시나리오 / 실패 복구

- 새 게임→20초 인트로 스킵→즉시 조작→WASD→E 조사→전령 대화→편지 비교→기록책→지도: 입력/카메라/플래그 정상.

- 지도 최대 확대/최소 확대 20회, 커서 앵커 20px 이하 오차(1920×1080 기준 제안), 핀 좌표 유지, LOD 전환 시 빈 화면 없음.

- 지도 핀 설치→게임 저장→로드→핀 위치 복원. 목적지 다른 공간일 때 route graph 검증.

- 대화 도중 Esc, 일시중지, save/load, 화면 해상도 전환, 30FPS 조건에서 카메라와 입력 소유권 원복.

- 도깨비 설화 경험 여부와 무관하게 서장 및 1장 완료 가능.

- 역마 자동 이동 시 이벤트 근처 감속/하차, 진행 중 취소, 닫힌 성문·다리 교차 지점 막힘 방지.

- 타이틀 중 카메라 경로/폰트 UI 좌표 16:9/16:10/4:3 확인.

- 성황당에 기존 제의 소품이 있으면 신규 중복 오브젝트 생성하지 않음.

# 14. 남아 있는 결정 / 현장 확인 사항

- 현재 새 게임 스폰(-2952,184)의 실제 화면과 남원읍성/이겸 거처 새 후보 위치의 지형 충돌을 Godot로 렌더링해 확정할 것.
