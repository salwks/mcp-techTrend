## 1. 최상위 불변 방향
- 설화록은 설화를 따라가기만 하는 게임이 아니라, 설화 속 세계를 관찰하고 이해하고 그 안에서 자신의 일을 수행하는 게임이다.
- 설화의 주인공은 원작 인물이다. 플레이어는 원작 인물의 핵심 선택과 행동을 빼앗지 않는다.
- 설화 하나를 끝낼 때마다 이야기만 소비되는 것이 아니라, 플레이어가 세상에서 할 수 있는 행동과 맡을 수 있는 책임이 축적될 수 있다.
- 초반에는 일을 받고, 중반에는 문제를 해결하고, 후반에는 판단과 책임을 맡는 방향으로 성장한다.
- 기본 문법 `OBSERVE → CONNECT → DECIDE → ACT → RESULT`. 모든 설화에 다섯 단계를 같은 비율로 억지로 넣지 않는다.

## 2. 상위 문서
`seolhwa/docs/production/SEOLHWAROK_GAMEPLAY_ARCHITECTURE_FINAL_v1.0.md` — 최소: OBSERVE/CONNECT/DECIDE/ACT/RESULT, 성장 3단계(Stage 1 길손 · Stage 2 해결사 · Stage 3 책임자/공적 역할), 모듈(STORY · ACTIVITY · PROBLEM · PROGRESSION), PROGRESSION 개념 분리(ROLE · REPUTATION · AUTHORITY · RELATION). 이번에는 Role/Reputation/Authority/관직을 구현하지 않고 미래 구조만 고정한다.

## 3. 절대 하지 않을 것
전체 직업 시스템 · 관직 승진 · 과거시험 · 평판 시스템 전체 · 도덕성 수치 · 경제 시뮬레이션 · NPC 생활 AI 확대 · 대규모 퍼즐 프레임워크 · 별도 '관찰 모드' · 레이튼식 전용 퍼즐 화면 여러 종 · 춘향 II-A 재작성 · 춘향 구출 분기 · 변학도 암살 · 플레이어가 몽룡을 암행어사로 만드는 구조 · 플레이어의 증거가 어사출두를 발생시키는 구조. 공통 코드는 실제로 2개 이상 콘텐츠에서 재사용될 최소 계약만.

## 4. 오누이 = 서사형 튜토리얼 보강
갈아엎지 않는다(추적·전투·아이 보호·야간 위기·원전 결말·사건 흔적 유지). 관찰 3~4개 + 아주 쉬운 연결/판단 한 번만 추가. 문법 `본다 → 기록된다 → 몇 가지 정보를 연결한다 → 행동한다`. 별도 관찰 모드 금지 — E, inspect/examine, discover, journal 재사용. 후보: 큰 짐승 발자국, 높은 나무의 긁힌 흔적, 한쪽으로 눌린 풀, 외딴집 주변의 겹치는 사람/짐승 흔적(실제 동선 보고 3~4개). 표현: 나쁜 예 "호랑이가 북쪽으로 갔다." 좋은 예 "진흙에 사람 발보다 훨씬 큰 자국이 남아 있다." 관찰 2~3개 뒤 방향/위험 판단("어느 쪽 흔적을 먼저 확인할까?"). 틀려도 막히지 않음 — 짧게 잘못된 장소 → 추가 흔적 → 본 흐름 복귀(Fail Forward). FIXED_BEAT·결말 불변.

## 5. Activity/Problem 최소 모듈 (춘향 II-B에서 첫 검증)
거대한 범용 시스템부터 만들지 않는다. 먼저 StoryRunner, story_director, journal, inspect, choice, flag, item, prop 상태를 조사하고 기존 2~4개 조합으로 되면 그것을 쓴다. 공통화가 꼭 필요한 부분만 얇은 계층. "춘향 전용 술·쌀·상소 코드"가 아니라 다른 관아·설화에서 재사용 가능한 문제해결 단위.
- Activity: 이번 범위만 inspect · compare · classify 또는 connect · decide. 필요 없는 타입을 미리 만들지 않는다.
- Problem: 여러 관찰/Activity와 결과를 한 문제로 묶음 — 개념 예 id, sources, observations, required/optional, decisions, fail_forward, result flags(실제 스키마는 코드 스타일에 맞게).
- 공통 코드에 `if case == ...` 금지.

## 6. 기록 정보의 성격
장기적으로 본 것/들은 것/추정/확인. journal이 전부 지원하지 않으면 이번에 journal 전체를 리팩터링하지 않는다. 최소한 직접 본 사실과 누가 말한 내용은 반드시 구분. 추론/확인은 사건 flag 또는 얇은 metadata로.

## 7~10. 춘향 II-B ACT 13 (첫 검증 사례)
흐름 유지: 술·쌀·상소 세 일, 순서 자유. "변학도가 나쁘다"는 설명이 아니라 관아 안에서 직접 일을 하며 구조를 경험. 단순 `이동 → E → 대화 → 선택`이 아니라 최소 `관찰 → 업무 → 정보 연결 → 판단 → 행동`.
- 술: 관아 지시/표·문서 확인 → 수레의 실제 술독 확인 → 상인의 말 → 장부/명령과 실제의 차이 인식 → 처리 결정. 선택 의미 유지(전부 가져간다 / 한 독 남긴다 / 상인의 말을 기록한다; 표현 다듬기 가능). 정답 맞히기가 아니라 부당함을 알고 어떻게 가담할지 결정.
- 쌀: 징발 지시량 · 실제 실린 가마 수 · 농민 진술의 관계를 이해. 선택(전부 / 한 가마만 / 아전에게 다시 묻기) 유지. 어느 선택도 핵심 사건을 막지 않음 — 그 집 피해와 결말 후 복구가 달라짐.
- 상소: 노인의 말은 기본 '들은 정보', 자동 사실 확정 금지. 잔치에 쓴다고 소를 가져감 · 책을 든 선비가 관아 일을 묻고 기록(이겸 가능성, 확정 안 함) 유지. 실제 행정 흐름처럼: 사연 듣기, 문서가 어디로 가야 하는지 확인, 아전의 "내일 와" 처리와 실제 처리 상태 비교, 기록 여부 판단. 탐정 퍼즐로 키우지 않는다.

## 11. 시나리오 충돌 해석
"증거 조합 퍼즐 없음"은 삭제·반대 해석하지 않는다. 뜻: 변학도를 무너뜨리거나 어사출두를 일으키려 증거를 모아 조합하는 퍼즐은 없다. 허용: 관아 업무를 하며 장부·물자·주민 말을 관찰·이해·처리하는 문제해결. II-B Activity는 범인을 밝히는 증거 퍼즐이 아니다 — 플레이어는 이미 무엇이 부당한지 안다. 문제는 그 구조 안에서 무엇을 보고 어떻게 행동했는가. 관련 시나리오/결정 문서를 이 뜻이 모호하지 않게 최소 수정.

## 12~17. ACT 13 이후 원전 흐름 그대로
순서: 술·쌀·상소 → 몽룡 귀환 → 월매 집 → 옥중 상봉 → 생일잔치 → 시 → 어사출두 → 피해 복구 → 춘향 석방 → 마지막 선택 → 광한루 결말. FIXED_BEAT는 Activity 성공 여부와 무관하게 발생.
- 몽룡 귀환: 준비된 거지 차림 자산, 마패는 필요한 순간만. 플레이어가 정체를 만들거나 추리해서 어사출두를 발동하지 않음.
- 옥중 상봉: 몽룡이 스스로 찾아감. 관아 관계가 좋으면 약간 도울 수 있으나 실패해도 방자/월매 등 다른 경로로 FIXED_BEAT 발생.
- 잔치: 준비 자산 그대로 — EventCrowd 14(손님 8·기생 4·시중 2), 사령/포졸은 고정 story actor, 차일·보계·교의·병풍·독상·술 수레. 잔칫상 간격: 사령 줄은 움직이지 않는다. II-B 실제 actor 동선을 붙인 뒤 측정, 목표 실제 보행 폭 ≥ 1.6m, 미달이면 상만 축 쪽으로 약 0.5m, 중앙 통로 유지.
- 차일: C62 유지(공식 8A = FURLED, 낮은/가까운 잔치 구도 = SPREAD, 컷 전환 때만 변경, 천 애니메이션 없음).
- 어사출두: 보스전 없음, 플레이어는 싸우지 않음. 같은 관아에서 사령/손님/기생 자세 변화, 변학도 cower, 몽룡 마패, 음악 중단, 말발굽, "암행어사 출두야". EventCrowd·고정 actor는 같은 사람/노드/자리에서 자세만 바꿈.

## 18~20. 결과의 쓰임
- 도덕 점수 합산 금지. 구체적 행동 flag로 기억(예: wine_discrepancy_seen, wine_recorded, wine_left, rice_order_seen, rice_left, rice_reasked, old_man_heard, petition_processed, restraint_obeyed/loose/refused — 이름은 현재 규칙에 맞춤). 결말에서 그대로 다시 사용.
- 피해 복구: 몽룡은 이미 자기 조사를 끝냈다. 플레이어 기록은 몽룡을 성공시키는 증거가 아니다. 직접 본/들은 내용은 주변 피해 복구에 쓴다(술값 지급 · 쌀 반환/피해 감소 · 노인 민원 재조사). 본 것/들은 것을 대사에서도 구분("쌀을 더 가져간 것을 보았습니다." / "소를 가져갔다고 들었습니다.").
- 마지막 춘향 반응: II-A 포승 선택(잡음/느슨/놓음)을 반드시 회수. 점수 평가 없이 춘향이 기억.

## 21. Activity 재사용 준비
관직 시스템 없음. II-B Activity가 사건 코드에 강결합되지 않게. 춘향 종료 뒤 같은 시스템으로 짧은 남원 관아 일거리 1개를 만들 수 있을 정도의 재사용성 — 가능하면 개발용 fixture/demo 1개(예: '관아 창고 장부 대조'). 직업 UI·숙련도·보상 경제 금지. 재사용 검증용이어도 된다.

## 22. 저장/불러오기
Activity/Problem 중간에도 저장/불러오기가 깨지지 않게. 필요한 상태만 사건 namespace에. 공통 시스템이 사건 전체 상태를 따로 복제하지 않음. 로드 시 완료한 관찰 재생 금지 · 처리한 물건 원상복구 금지 · 결정 flag 유지 · FIXED_BEAT 중복 실행 금지.

## 23. 테스트
기존 전체 이야기 시험(지시 당시 60개, 현재 64개)이 모두 다시 PASS. 새 시험 최소:
- 오누이: 관찰 단서 등록 · 2개 이상 관찰 뒤 초급 추론 가능 · 틀린 판단 Fail Forward · FIXED_BEAT/결말 불변 · 저장/불러오기.
- Activity 공통: 데이터 계약 검사 · 다른 case id 하드코딩 없음 · source 누락/잘못된 id 검증 · 완료 flag 중복 방지 · save/load.
- 춘향 II-B: 최소 세 갈래 전체 실행 — 술/쌀/상소 순서 자유 · 각 업무 1회만 완료 · 잘못된/소극적 판단이어도 진행 · 몽룡 귀환 · 옥중 상봉 · 잔치 · 시 · 어사출두 · 변학도 처벌은 Activity와 무관 · 피해 복구만 Activity 결과에 따라 변화 · 춘향 석방 · CASE_NAMWON_CHUNHYANG_COMPLETE = true · outcome "RELEASED" · 마지막 포승 기억 반영.
- 잔치: EventCrowd 14 · 포졸/사령이 EventCrowd에 섞이지 않음 · 동일 노드 pose change · 사령/상 사이 실제 폭 검사 · 차일 C62 · reveal 이후 변학도 cower.
- 전체 `tools/run_story_tests.sh`, SCRIPT ERROR 0.

## 25. 조작감
Activity 때문에 조작을 빼앗지 않는다. 대화/퍼즐창이 길어져 "읽는 게임"이 되지 않게. 현장 이동 · 물건 직접 확인 · 사람에게 직접 묻기 · 필요한 곳 직접 가져가기 유지. 별도 UI는 정보 연결·최종 판단 때만 최소.

- 오누이: "표시를 따라간 것이 아니라 주변을 보고 위험을 알아냈다."
- 춘향: "변학도가 나쁘다는 설명을 들은 것이 아니라, 내가 그 관아에서 일하면서 어떻게 사람들의 것을 빼앗는지 직접 봤다."
- "내가 한 작은 행동은 춘향전의 결말을 바꾸지는 않았지만, 누군가의 피해와 나에 대한 기억은 바꿨다."

## 30. Git
