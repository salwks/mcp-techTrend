## 1. 기존 구현 요약 — 사실

### 1.1 settlement v2 (Python 오프라인 굽기, Layers 0–2만 구현)

**모듈 구성.** 각 모듈의 역할은 다음과 같다.

| 모듈 | 역할 |
|---|---|
| `site.py` | 땅 읽기: 경사·방위·물 거리·범람 화면·쓸 땅 성분 |
| `program.py` | 수용력 먼저 프로그램. 계층별 의무시설, full/compact 변형, 가구 수 정수 풀이 |
| `frame.py` | 틀 4가족(평지성·평산성·산성·무성곽), 관아 터, 문·수문, 회랑 |
| `routing.py` | 격자 A*·경사 측정 |
| `validate.py` | 독립 검사 L0.*·L1.*·L2.*·plan.* |
| `svg.py` | 도면 |
| `rules/default.json` | 모든 수치에 단위·source·confidence를 붙인 규칙 |

**결과(impl §6).** 실제 4곳 가운데 3곳은 배정 면적 부족으로 insufficient_capacity가 났다. 남원도 core 안에서는 부족했다. 8곳 결정성은 바이트 동일(64파일)이고, pytest는 21개 통과했다.

**식별자.** `geometry.stable_id`(geometry.py:158)는 정규화된 기하를 SHA1로 해시한 내용 파생 ID다.

**잠금.** 실제 지역 어댑터는 `locks=[]`를 고정으로 넣는다(adapters/region.py:289). 이야기 지점을 잠금으로 받지 않는다는 뜻이다.

**미커밋 변경(다른 작업자) — 사실.** 바뀐 내용은 세 묶음이다.

- **허용 영역 자동화.** `envelope.py`가 허용 영역(allowed)을 자동으로 만든다.
  - 읍치는 고리 단위로 최대 400 m까지 넓혀 계층 최소 면적을 채운다.
  - 마을은 보행 150–250 m 범위에서 max_households 상한에 맞춘다.
- **범람 단위 변경.** 범람 단위가 source_m(+1/+3/+5)에서 world_m(+0.5/+1.5/+3.0, 배제 +1.5)로 바뀌었다. 근거는 "coordinator 결정 2026-10-23"으로 기록되어 있다.
- **산 길 별도 등급.** 산 길에 별도 등급을 둔다. 지속 경사 15%, 32방향 격자, 폭 4.8 m, 갈지자 비용을 적용한다. 대상은 산성 가족과 sanchon·sanseong_refuge 프로필이다.
- **기타.** civic.spacing을 6에서 12 m로 늘렸다. 성 틀 곡선을 Chaikin으로 다듬는다. 목적 함수에 capacity 가중치 0.25를 더했다.

**L3–8.** 설계만 있고 구현은 없다. 구역·길·필지·집 짜임·경계(BoundarySpan)·굽기 계약을 다룬다.

### 1.2 integ 게임

**건물 빌더 `kit/bldg/*`.**
- 사양은 Dictionary이고 프리셋이 22개다(`_spec.gd:152-636`).
- 칸마다 폭이 다른 배열을 쓴다: `wings[].bays[].w`, `depth[]`.

- 기단·툇마루가 있다. 굴뚝 위치는 고정 오프셋이다.

- 검사: ROOFCHECK·CORNERCHECK·FACECHECK·ROOFTEST·bldg_integ·bldg_rollout.

- todam(두께 0.45)·stone_wall(0.55)·싸리울이 있다.

- `gate.gd`는 9종이고, 문짝이 안쪽으로 열리며 접근 앵커가 있다.
- 담 단면(기초·양쪽 지면·속 구성), 수구, 사괴석·토석담 구분은 없다.

- ID는 순번 기반이다(`"%s_lot%03d"`, `"%s_%s%02d"`).

**랜드마크 키트 `kit/landmark/*`(106개 .gd, `catalog.json`) — 처음 초안에서 빠졌던 것(Codex 지적, 직접 확인).**

## 5. 작업 묶음(배치 실행 계획) — [제안]

원칙:
- 데이터 계약을 먼저 정한다.
- 남원 고유 배치는 마지막 적용 단계로 미룬다.
- 묶음마다 두 지형·두 seed에서 V를 실행한다(19 §4-2).
- 모든 묶음에서 보호할 것: 이야기 앵커·사건 ID, 사용자 저장(읽기·덮어쓰기 금지), 기존 통과 검사, 다른 작업자의 미커밋 변경.

WP7b 공공 시설 문법, WP9 재료·노후, WP10 식생: WP8과 병렬 가능.  WP13 V 하네스: WP0부터 계속.

### WP0 기준선 고정(코드 변경 없음)

- **목표:** 이후 묶음이 망가뜨리면 안 되는 것을 목록으로 고정한다.
- **입력:** 기존 검사, 이야기 파일(`placement_story_*`, `story_director` 앵커), 저장 시험.
- **출력:** 기준선 보고. 검사별 마지막 통과 수치, 앵커·ID 목록, 저장 필드 중 배경 ID를 참조하는 것.
- **파일:** 읽기만 한다. `scripts/story/story_director.gd`, `scripts/region/placement_loader.gd`, `tests/save/save_guard_test.gd`, `tools/bldg/*_check.gd`, `tools/settlement/tests`.
- **인수:** V16의 기준 목록이 완성되어 있을 것.
- **위험:** 저장이 배경 ID를 간접 참조하는지 미확인. 원격 저장 경로 실수가 2회 있었으므로 게임 인자는 `--` 뒤에 둔다.
- **차단:** 없음.

### WP1 공통 데이터 계약 v1(스키마)

- **목표:** TOOL-01 객체의 JSON Schema와 공통 메타를 정한다.
  - 대상 객체: RegionProfile(scale_policy 포함), SourceRecord, TerrainPatch, WaterReach, HabitatPatch, Route, Parcel, Boundary, Opening, Building 서술자, ActivitySite, SurfaceProfile, WallSection.
  - 공통 메타: stable_id, provenance, rule_version, status, lock_scope, revision.
- **입력:** 04, v2 `schemas/*`, L3-8 레코드 예시, `_spec.gd` 스키마 주석.
- **출력:** `tools/settlement/schemas/` 또는 공통 위치에 둔 스키마와 v2 rules confidence ↔ status 대응표. 결측과 0을 구분한다.
- **인수:** V18(가설 표시·자동 확정 없음), 스키마 단위 시험, K1 변환 기록이 있을 것.
- **보호:** v2 기존 스키마는 버전을 올리고 이전 출력도 읽힐 것.
- **위험:** 과설계. 1차는 필수 항목만 둔다.
- **차단:** 없음(지역 값은 unknown으로 둔다).

### WP2 식별·잠금·이야기 보호
