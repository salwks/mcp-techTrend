# placement-east 보고서: 남원 읍내를 뺀 동쪽 배치 (JL_NAMWON_UNBONG)

- 담당 범위: x > −2300. 대상은 여원재, 이백, 운봉 읍치, 황산대첩비, 비전, 인월, 실상사, 산내, 반선, 들마을 3곳, 길가 주막, 도강점이다.
- 시대: 1870년 전후.
- 산출물: `region_data/JL_NAMWON_UNBONG/placement_east.json`. 항목은 307개이고 계약서 §8 형식을 따른다.

## 1. 다시 만들기

```bash
python3 tools/placement/east.py           # placement_east.json과 평면도 shots/placement/east_plan_*.png를 만든다
python3 tools/placement/east.py --noplan
```

- **결정적이다.** 장소마다 `random.Random(고정 seed)`를 쓴다. 키트 모양을 정하는 seed는 자리 찾기 난수와 따로 둔다. 같은 입력으로 두 번 돌리면 md5가 같다.
- **키트의 실제 크기는 Godot으로 잰다.** `tools/placement/east_measure.gd`(headless `-s`)가 build() 메시 AABB, 삼각형 수, 앵커를 `tools/placement/east_bounds.json`에 캐시한다. 캐시에 없는 kit+params만 새로 재고, 그다음 처음부터 다시 배치한다.
- **코드 구성**
  - `east_terrain.py`: height.png(16bit)와 landuse.png를 읽고, 하천·도로까지의 거리를 계산한다.
  - `east_place.py`: 회전 사각형(SAT) 겹침 검사와 자리 찾기를 맡는다. 자리를 찾을 때 검사하는 것은 다음과 같다.
    - 경사(footprint 안 높이차)
    - 하천 가장자리에서 떨어진 거리
    - 도로 가장자리에서 떨어진 거리
    - 토지이용(물·바위)
    - x 하한
    - 길과 집 사이에 내가 끼어 있지 않은지
  - `east_plan.py`: 평면도를 그린다.
  - `east.py`: 장소별 구성을 정한다.
- **규칙**
  - 건물은 가까운 길과 나란히 놓되 ry는 ±30° 안으로 둔다. 남향이 기본이다.
  - 길이 집의 남쪽(카메라 쪽)에 오는 자리를 더 좋게 친다.
  - 관아·역·실상사는 담 안 마당과 문 앞 진입로를 `reserve` 사각형으로 비워 둔다. 이 사각형은 파일에 쓰지 않고, 다른 건물만 들어오지 못하게 막는다.
  - 운봉 관아와 인월역 조각은 한 높이(`y` = 조각 중심 높이의 중앙값)로 고른다.
- **겹침 검사:** 전수 검사에서 0건이다. 의도한 겹침(성황당과 신목, 담 모서리)과 다리는 뺐다.

## 3. 도강점(x > −2300의 crossings 전부)

종류는 region.json `type`을 따랐다. 여울(D급 개울)에는 징검다리를 놓았다. 다리 길이 = 하천 판 폭(max(w/2, 2.6)·2) ÷ |cos(길과 하천 법선 사이 각)| + 여유. 놓는 방향은 길 방향(로컬 z)이다.

| crossing | 종류 → 키트 | 길이(m) |
|---|---|---|
| ramcheon_unbong_ford, _2 (람천 B) | 징검다리 | 16.8 / 22.0 |
| x_tongyeong__r041_3 | 징검다리 | 8.0 |
| x_tongyeong__r044_4 | 돌다리 | 10.3 |
| x_tongyeong__r044_5 | 1m 떨어진 같은 자리라 r044_4에 합쳤다 | — |
| x_tongyeong__r068_6, r070_8, r083_9 | 돌다리 | 8.2 / 8.7 / 9.3 |
| x_tongyeong__r069_7 | 징검다리 | 8.8 |
| haetal_bridge (람천 B) | 섶다리 | 26.0 |
| x_inwol_bans_r030_11 | 해탈교에서 5m 떨어져 있어 해탈교에 합쳤다 | — |
| x_inwol_bans_r032/r036/r075/r077/r078 | 징검다리 | 6.2~6.7 |
| x_baemsagol__r080_21/22/23 | 징검다리 | 6.7 / 9.7 / 8.6 |

- `y`는 null로 두었다. 다리는 로더가 둑 높이를, 징검다리는 로더가 하천 수면을 잡는다. 생성기가 계산한 값은 로그로만 남긴다.
- 추가: 인월 람천 섶다리 1개. 마을끼리 잇는 다리이고, region.json에 길과 도강점이 없는 자리다. id는 `ea_iw_seop_bridge_01`이다.

## 4. 확인

- **평면도** (`shots/placement/east_plan_*.png`): yeowonjae, unbong, hwangsan, inwol, silsangsa, sannae, banseon, ibaek, auto_03/04/06. 그린 것은 음영기복, 토지이용, 하천, 도로, 회전 footprint, 정면 표시(흰 선)다.
- **게임 화면** (`shots/placement/east_*.png`): 로더가 준비된 뒤 `region.tscn --warp --cam=70~120,40~45 --notilt`로 찍었다.
  - unbong_gwana, unbong_market, unbong_west, unbong_night(21시, 게임 거리 45m)
  - yeowonjae, hwangsan, inwol_market, inwol_south, inwol_game(기본 게임 시점), silsangsa, sannae, banseon, ibaek
- **찍은 화면을 직접 보고 고친 것**
  - 운봉 관아 담 안에 초가가 들어가 있었다. 담 안 마당을 `reserve`로 막았다.
  - 실상사 주막이 천왕문 바로 앞에서 진입로를 막고 있었다. 주막을 서쪽으로 옮기고 진입로를 `reserve`로 막았다.
  - 산내 집들이 만수천 건너편, 길 없는 쪽에 놓였다. 길과 집 사이에 내가 있으면 그 자리를 버리게 했다.
  - 외삼문이 담과 겹쳤다. 문 틈을 5.6m에서 7.4m로 넓혔다.
  - 인월역 기와집이 뒷담과 겹쳐 배치를 고쳤다.
  - 수렴하지 않던 크기 재기 반복을 고쳤다.
- **로더 결과:** `PLACEMENT files=2 items=535 placed=665 missing=0`(남원 배치 포함), 오류는 없었다.

## 5. 성능

- 동쪽 전체 키트 삼각형 합은 57.5만이다. 권역 전체에 흩어져 있다.
- 한 화면(둘레 60m 안 키트 합) 최대값:

| 장소 | 삼각형 |
|---|---|
| 운봉 읍치 | 11.5만 |
| 인월 | 8.1만 |
| 이백 | 5.2만 |
| 나머지 | 4.4만 이하 |

- 목표 50만보다 훨씬 낮다. 식생 삼각형은 따로다.
- fps: 같은 맥에서 다른 에이전트가 돌던 중에 찍은 값이라 흔들린다. 마을 화면에서 56~60이었다.

## 6. 고증 근거와 가설

1. **운봉현 관아(가설):** 위치 근거는 region.json `unbong_gwana`다(OSM 운봉읍 부근, 가설). 현은 부(府)보다 작아 외삼문, 동헌 5칸, 내아 3칸만으로 담 36×36m 안에 줄였다. 객사·작청·내삼문은 뺐다. landmark 목록의 `hyeon_gwana` 키트가 없어서 조각을 직접 조합했다. 자리는 도로를 피하려고 region.json 좌표에서 약 10m 안쪽으로 찾았다.
2. **운봉장·인월장:** 장날과 규모는 확인하지 못했다. kit-village 권고대로 산간 장은 좌판 위주로 하고 가가는 적게 두었다.
3. **인월역:** 역참 위치와 규모 모두 가설이다(region.json도 가설). 역사, 마방 2, 담만으로 줄였다.
4. **여원재:** 성황당·고갯마루 주막·아랫주막은 가설(terrain-data 가설 7)이다. 마애불은 키트가 없어 놓지 않았다.
5. **실상사 앞 장승:** 실상사 석장승(1725년, 돌)은 현존한다. 키트가 나무 장승이라 대신 놓았다(돌 장승 키트 요청 참고). 위치는 해탈교 동쪽 길가로 두었다.
6. **인월 람천 남쪽 마을과 섶다리**는 가설이다. 장꾼이 오가는 다리로 넣었다.
7. **들마을 3곳, 길가 주막 6곳, 물레방아 4곳**의 자리는 입지 규칙(완경사, 물가, 길가)으로 정한 것이고 사료는 없다.
8. **도강 형식:** terrain-data의 자동 기본값(B 섶다리, C 징검다리, D 여울/대로 돌다리)을 따랐고, 여울에는 징검다리를 놓았다. 모두 가설이다.
9. **건물 수와 간격**은 K=0.30으로 압축한 땅에 맞춘 근사다.

## 7. 요청

- **terrain-data:**
  - 통영별로가 운봉 읍치에서 (844,−746)까지 들어갔다가 같은 길로 되돌아 나간다(points 240~256). 실제로는 읍치를 지나 인월로 가는 길이어야 할 것 같다. 길이 바뀌면 `python3 tools/placement/east.py`를 다시 돌리면 된다.
  - 인월 람천 남쪽 마을로 가는 마을길·도강점이 있으면 섶다리가 정식 도강점이 된다.
- **terrain-engine:**
  - `ea_iw_seop_bridge_01`은 crossings 목록에 없는 다리다. 로더가 params로 만드는 walk 면이 하천 막기를 풀어 주는지 확인해 달라.
  - 마을 터(landuse 6)와 터 고르기로 칠한 마당 위에서 길이 거의 안 보인다(운봉·인월 화면). 길(landuse 4) 색이 마당색보다 위에 오면 좋겠다.
- **kit-landmark:**
  - `hyeon_gwana`(현 관아 배치형)가 생기면 내 조합을 그것으로 바꾸겠다.
  - 마애불 바위(`maaebul_rock`)가 생기면 (−40.8, −938.8)에 놓겠다.
- **kit-village:** 돌장승(실상사 석장승)이 있으면 좋겠다.
- **총괄:** 새 파일(`tools/placement/east_measure.gd` 등)의 import·uid는 총괄이 처리해 달라. `godot --import`는 돌리지 않았다.
