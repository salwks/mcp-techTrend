# 2026-10-13 — 16:9 기준 화면(1920×1080) · 시작 메뉴 움직이는 바탕

사용자: 16:9 기준 해상도로 바꾸고 화면 배율을 쓰기("당연하지") · 시작 메뉴 바탕을 새 그림으로 · 기존 「설화록」 제목 자리만 새 로고로.

## 1. 기준 화면 1920×1080

| 설정 | 전 | 후 |
|---|---|---|
| `display/window/size/viewport_*` | 1024×768 | **1920×1080** |
| `window/stretch/mode` | disabled | **canvas_items** |
| `window/stretch/aspect` | — | **expand** (16:9보다 넓으면 옆으로, 길면 위아래로 캔버스가 늘어난다 — 잘림·검은 띠 없음) |
| `window/size/resizable` | (기본) | true |
| 처음 창 | 1024×768 화소 | 그냥 실행하면 작업 영역 88% 안의 가장 큰 16:9(이 맥 2880×1610 작업 영역 → 2432×1368 화소). `--` 뒤 인자(시험·촬영)가 있으면 건드리지 않음, `--fitwindow`로 강제 |
| 전체 화면 | 없음 | **F11 · Alt+Enter**(`scripts/ui/window_keys.gd` — 루트 창 맨 뒤 자식이라 어느 메뉴보다 먼저 받는다) |
| 3D 장면 화소 | 창 × 화면 배율(레티나 2), 긴 변 3840 | 같은 규칙 + **2560×1440(약 370만 화소) 한도**(`MAX_RENDER_PIXELS`) — 예전 2048×1536(315만)과 비슷한 GPU 몫. `--scale=N`을 주면 한도 없이 그대로 |
| 한지 결 | `paper_ratio = 화면 배율` | `scene_vp 높이 / 768` — 장면 높이에 대한 결 크기가 예전과 같다 |
| 헤드리스 | 창 정사각에 가깝게(보이는 크기 1920×1920) | `fit_window`가 1920×1080으로 놓는다 — 시험이 16:9에서 잰다 |

- 맥에서 Godot 창 크기는 **화소**다(이 맥: 화면 2880×1800, 배율 2). 예전 1024×768 창은 화면에서 512×384pt였다.
- 3D는 `scene_vp` → 전체 화면 TextureRect라 창을 늘 꽉 채운다. UI는 캔버스(1920×1080 이상)와 함께 창에 맞춰 커지고 작아진다.

## 2. 글 크기 표(UiFonts — C64)와 화면 다시 맞추기

`UiFonts.k(보이는 크기)` = 높이/1080(예전 각 화면이 `높이/768`을 따로 셈 — 모두 이 함수로 바꿈). 표는 1080 캔버스 화소, **예전 값 × 1.45**(화면 높이 비율로 보면 1080/768 = 1.406보다 조금 크게).

| | 전(768) | 후(1080) |
|---|---|---|
| TITLE · HEAD · NAME · BODY | 44 · 34 · 30 · 28 | **64 · 50 · 44 · 40** |
| DETAIL · KEYS · NOTE · MIN | 24 · 22 · 20 · 18 | **35 · 32 · 29 · 26** |
| MAP_HUB · MAP_TOWN(고을 이름) | 26 · 24 | **38 · 35**(비율 그대로) |
| 그 밖의 지도 글(MAP_MIN·LABEL·MINOR·GLYPH·PANEL·KEYS) | 26 | **38**(= 고을 이름 이상) |
| 아래쪽 글(C43): 자막 · 안내 띠 · E 안내(처음) · 키 안내 · 소지품 | 40 · 30 · 32(38) · 27 · 25 | **58 · 44 · 46(55) · 39 · 36** |
| 아래쪽 줄 자리 BOTTOM_ITEMS · KEYHINT · PROMPT · HINT | 46 · 94 · 152 · 160 | **66 · 134 · 216 · 226** |
| 기록책 세로 본문 | 25 | **36** |

- 각 화면의 `숫자 × k` 자리·크기는 모두 × 1080/768로(스크립트로 바꾸고 하나씩 봄): story_ui(대화·선택·카드·알림·자막·도장·전투 HUD·말풍선), journal_view, documents, save_menu, options_menu, spirits(호신물 칸), fast_travel(역마 창), travel_overlay(건너뛰기 단추), region_main(말·배 안내 · 왼쪽 위 HUD · 불러오기 화면 · 떠나는 화면), 이야기 제목 카드(남원 75 · 설화록 133).
- k를 곱하지 않던 테·여백·간격(한지 판 여백, 키 칸, 외곽선)도 같은 배로.
- 지도(region_map): 화면 고정 크기 상수 ICON_S 1.6→2.25 · HALO 9→13 · LABEL_PAD 3→4 · 범례 기호 2.0→2.8 · 방위 · 10리 자 · 확인 상자 · 표지 설명 여백. **px/m 문턱도 같은 배로**(MAX_K 6→8.4 · TIER3_K 1.6→2.25 · 고을 지도 문턱 1.15→1.62) — 같은 확대 단계에서 화면에 보이는 땅 넓이가 예전과 같다(글이 커진 만큼 이름이 더 솎이지 않게). 확대와 상관없는 지도 글 크기 규칙은 그대로.

### 줄인 '1024×768에 넣기' 타협
- **지도 오른쪽 판: 쪽 넘김(범례 / 사건·역참) 없앰** → L로 열고 닫는 한 판(범례 두 단 + 현재 사건 + 역참, 넘치면 휠). 판 너비 vs.x×0.3(470~680). 16:9라 판을 열어도 지도가 4:3 때보다 넓다.
- **역마 창 목록 글**: 좁아서 26으로 줄였던 것을 BODY 그대로(40)로.
- **Esc 메뉴 두 단은 남겼다**: 세로 공간은 글과 같은 배로 커져(1080/768) 열일곱 줄을 한 단에 넣으면 1080을 넘는다. 두 단은 이제 가로가 넉넉해 답답하지 않다(`shots/res_1080/ui/esc_menu.png`).
- 선택지 12개 넘으면 두 단 — 그대로(세로 문제라 같음).

## 3. 카메라 — 세로 시야 지키기

- `Camera3D.keep_aspect = KEEP_HEIGHT`(Godot 기본값을 명시 · region_main). fov는 **세로 시야** — 4:3 때 짠 모든 구도(기본 40° 시점, 대화 구도, 공식 틀 1A·5A·6A·8A·10A·12A·14A·17A·18A, 동아줄, 전경, 남원 여는 장면)의 세로 틀이 같고, 16:9에서는 좌우가 더 보인다.
- **다시 짠 장면 없음.** 가운데 4:3 띠가 예전 저작 틀과 같으므로 주인공·대상이 틀 밖으로 나가는 일이 없다. 8A 시험(prep_test `_ndc_x_8a`)은 4:3 저작 틀 기준 NDC로 재는 것을 그대로 두고 주석을 달았다(16:9 전체 화면에서는 × 0.75 — 사령 줄이 가장자리가 아니라 틀 안쪽에 보인다).
- 이벤트 군중 LOD의 화면 반각 근사(fov/2 × 1.45 + 6°)는 16:9 fov 30·40에서도 실제 가로 반각(25.5°·32.9°)보다 넓어 그대로.
- 고친 버그: 남원 수수밭 미끼 '틀 안' 판정이 장면 뷰포트(scene_vp) 화소를 창 크기로 나눴다(헤드리스에서만 맞았다) → scene_vp 크기로.
